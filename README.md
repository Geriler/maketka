# Макетка

3D-песочница электрических цепей в браузере. Детали ставятся на макетную, печатную или SMD-плату, соединяются проводами и дорожками, а схема считается по-настоящему: токи, напряжения, нагрев, переходные процессы. Два режима: свободная **песочница** и **карьера**, где компоненты открываются по цепочке — от транзистора до счётчиков, АЦП и стабилизаторов.

## Песочница

- **Платы:** макетная (400 точек), печатная с медными дорожками, плата под SMD (посадочные места появляются под деталью, выводные детали делают себе отверстия). Медь, которая касается чужой меди, соединяется с ней, как на настоящей плате: пересечь дорожку можно перемычкой или, на двусторонней плате, по другой стороне. Двусторонняя (печатная и под SMD): дорожки и снизу (видны синим сквозь плату), переходы между сторонами — клавиша V, пока ведёте дорожку; SMD-площадки только сверху, отверстия — с обеих сторон. Платы ставятся, двигаются и меняют размер.
- **Детали:** резисторы (выводные и SMD), конденсаторы, диоды и стабилитроны, светодиоды, лампа, биполярные и полевые транзисторы (в том числе SMD), кнопка (с дребезгом или без), тумблер, потенциометр, реле, семисегментный индикатор, батареи.
- **Приборы:** лабораторный блок питания (0–30 В, ограничение тока), мультиметр, осциллограф.
- **Микросхемы:** заводские (в том числе ПЗУ 74S288 — содержимое вписывается в таблицу — и ОЗУ 74LS219, которое без питания всё забывает; большая память 32K × 8 по даташитам: ОЗУ HM62256B — DIP-28 или SOP-28, и EEPROM AT28C256 — DIP-28 на 600 мил или SOIC-28, которую пишет и сама схема: байт за 10 мс, пока пишет — чтение отвечает опросом; чистая ячейка — 00; ОЗУ после включения — мусор, как в жизни, или нули — переключатель в настройках, проверки всегда берут мусор) и свои — любую сборку можно упаковать в корпус (DIP до 20 выводов, SOT-23-5/6, SOT-143, SOIC) и ставить как деталь; то, что в корпус не влезает (несколько микросхем), — в модуль: своя плата под SMD на однорядном штыревом разъёме (SIP-8…40), стоит на нём вертикально, место ограничено площадью платы, медь — с одной или с двух сторон; в меню они разложены по разделам: вентили, выбор, числа, память, счёт, шина, аналоговые, свои.
- **Физика:** детали перегреваются и сгорают, полярные включаются наоборот, есть режим разброса параметров в пределах даташитов.
- **Остальное:** принципиальная схема по ГОСТ строится сама, проекты сохраняются в браузере и в файл, отмена до 100 шагов.

## Карьера

Карта как дерево исследований:

- **Уроки** — шесть вводных, про приборы и первые цепи.
- **Уровни** — собрать компонент из выданного набора деталей в корпусе микросхемы; собранное открывается и становится деталью для следующих уровней. Цепочки: вентили (КМОП, РТЛ) → логика и сумматоры → триггеры, регистры, счётчики → дешифраторы и индикация → компараторы, 555, операционные усилители → стабилизатор → счётчик Джонсона и 74HC4017 → буферы с третьим состоянием → 74HC244 и регистр 74HC574 на шину → к процессору: 74HC157, счётчик 74HC161, регистр 74HC173, двунаправленный буфер шины 74HC245 → ПЗУ на диодах → прошиваемое ПЗУ 74S288; ячейки SRAM и DRAM на транзисторах, ОЗУ на регистрах → ОЗУ 74LS219 (он же открывает HM62256B; ПЗУ на диодах открывает и AT28C256); срез процессора на модуле SIP-20 (74HC157, 74HC283 и два 74HC173 — в корпус не влезают). Проверка уровня находит и входы микросхем внутри, оставленные висеть в воздухе, и медь, задевшую чужую (упакованная микросхема такие замыкания тоже несёт в себе).
- **Проекты** — устройства на столе из открытых микросхем: счётчик нажатий, секундомер, бегущие огни, ЦАП, вольтметр, АЦП последовательного приближения, порог с гистерезисом, 4-разрядный процессор с программой в ПЗУ и за ним 8-разрядный (два 4-битных среза, команда — 12 бит в двух ПЗУ) 8-разрядный из двух своих модулей «Срез», 32-разрядный из восьми (число — 4 байта в четырёх ПЗУ, выход — 32 площадки), «Декодер команд» — первая ступень своей ISA «М2» (16-битное слово: код операции и число; NOP, LDI, ADDI, OUT, JMP; что делать по коду — решает микрокод в EEPROM, таблицу вписывает игрок) и «Перенос и условный переход» (SUBI, JC, HLT: вычитание через XOR и перенос, флаг C в триггере, переход решает микрокод по флагу на адресе EEPROM) (уровень «Срез процессора на модуле»: регистр A, сумматор с переносом, выбор и регистр выхода на плате SIP-20) и загрузчик (после RST программа переписывается из EEPROM AT28C256 в ОЗУ HM62256B и исполняется оттуда; проверка стирает EEPROM после загрузки и следит, чтобы на шину не выводили две микросхемы разом) — на двусторонних платах под SMD (микросхемы в SOIC, дорожки сверху, где не развести — снизу через переходы; проверка ищет висящие входы, неподключённое питание микросхем и замыкания медью).
- **Ремонты** — готовые схемы со скрытой неисправностью: показаний деталей не видно, ищут приборами.
- **Задачи** — необязательные ограничения на уровнях: уложиться в N транзисторов, ток покоя, работа от 2 В.

Принципы: выводы и проверки настоящих микросхем — по их даташитам. Учебная ступенька (выдуманный компонент) нужна только для следующего уровня, дальше — настоящие микросхемы. В описаниях и подсказках нет готовых решений.

## Управление

| Клавиша | Действие |
|---|---|
| 1 / 2 | выбор / провод |
| T | дорожка; пока ведёте её на двусторонней плате, V — другая сторона (на узле — переход) |
| B / V | макетная / печатная плата |
| R | повернуть |
| F | перевернуть полярную деталь |
| Del | удалить |
| Esc | отменить начатое |
| Ctrl+Z / Ctrl+Y | отмена / повтор |

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # тесты решателя, деталей и уровней карьеры
npm run build      # сборка в dist/
npm run smoke -- --chrome /path/to/chrome   # проверка в браузере (после build)
npm run artifact   # один HTML-файл в dist-artifact/
```

## Как устроено

| Где | Что |
|---|---|
| `src/sim/solver.ts` | Метод узловых потенциалов; разреженное исключение с порядком минимальной степени. |
| `src/sim/simulation.ts` | Сборка ветвей, итерации Ньютона, шаг по времени (неявный Эйлер, 5 мс, при несходимости — дробление), нагрев. |
| `src/sim/devices.ts` | p-n переход: уравнение Шокли, обратный пробой стабилитрона, ограничение шага Ньютона. |
| `src/parts/` | Одна деталь — один файл: выводы, ветви для решателя, нагрев, 3D-вид, значок на схеме, панель. |
| `src/chips/` | Свои микросхемы и их модели: проверенная микросхема считается моделью по таблице, аналоговые — по транзисторам. |
| `src/model/` | Данные: типы деталей, топология плат. |
| `src/view/`, `src/ui/` | Three.js-сцена, схема, панели и экраны. |
| `src/career/` | Уровни, уроки, проекты, ремонты и их проверки. |
| `src/app.ts` | Состояние, ввод, установка деталей, отмена. |

Новая деталь — тип в `src/model/types.ts`, файл с `PartDef` в `src/parts/` и строка в `src/parts/index.ts`. Новый уровень — запись в `src/career/levels.ts` с набором, выводами и эталонной сборкой (`recipe`); тесты прогоняют эталон через ту же проверку, что и игрока.

## Упрощения

- Нет индуктивностей. Ёмкости переходов транзисторов завышены (иначе у схем с положительной обратной связью нет непрерывного решения); нет эффекта Эрли, β не зависит от тока.
- Шаг по времени 5 мс: всё, что быстрее, выглядит мгновенным; дребезг кнопки растянут, чтобы его было видно.
- Проверенные микросхемы считаются моделью: входы — пороги 30/70 % питания, выходы — источники с замеренным сопротивлением, без задержек распространения.
- Перегрев — игровая модель: тепло копится, пока нагрузка выше номинала.
- SMD-площадки — номинальные по IPC-7351, без паяльной маски; пересечение дорожек не проверяется.
